# 简报 → 播客（通用）

本 skill 独立于简报产出管线：输入**只认用户点名的简报文件**（逐条只读），不采集、不改简报、不碰任何上游数据目录、**不为补简报触发上游管线**。核心约定：一简报一至多集（每集 ≤15 篇）；对谈**逐篇改写、每写一篇追加一次稿本**；合成完全可重跑（段级缓存）。

## 简报契约（输入准入检查）

文件四条全满足才作输入；不满足的（含用户点名的）→ 拒绝并在最终答复报文件名与原因——**不替简报补行、不跑上游重写**，由用户定夺：

1. **条目结构**：论文条目以 `### ` 标题行起始；小节/统计标题用 `## `（不算条目）。
2. **收尾线**：每个 `### ` 条目以 `---` 线结束（兼篇间分隔与条目块界定）。
3. **成稿行**：文件末行有 `<!-- DONE YYYYMMDD … -->`——简报成稿唯一凭据；缺=半截稿或拉平前的旧版简报，拒绝并注明。
4. **归档**：文件位于 8 位日期文件夹 `reports\YYYYMMDD\` 之下——**批次日取文件夹名**，文件名本身不必含日期。

已知上游（三线简报均守此契约，本 skill 不限于它们）：repec-journal-brief `<Display>.md`（AER.md 等六刊）、repec-nep-brief `nep-<key>-<YYMM>.md`（零期轮不带月标作 `nep-<key>.md`）、ncpssd-briefing `briefing_<short>_<YYYYMMDD>.md`。同文件夹的 `00_总览.md`、`script_*`、`podcast_*`、`cache_*` 不是简报，按名排除。

## 路径约定

`<skill>` = 本 skill 目录。**数据不在本文件夹**——一切读写发生在用户点名简报所在的日期文件夹。

- 命名件件（{stem}=简报文件名去扩展名；{YYYYMMDD}=简报所在日期文件夹名；p{k}=集号）：
  - 对谈稿 `script_{stem}_{YYYYMMDD}_p{k}.md`
  - 成品 `podcast_{stem}_{YYYYMMDD}_p{k}.mp3`
  - 段缓存 `cache_podcast_{stem}_{YYYYMMDD}_p{k}\`（脚本自动建；删某段文件=强制重配该句）
- 单集简报（N≤15）同样用 `_p1`，不留无后缀命名。
- 合成脚本 `scripts\make_podcast.py`（依赖 `edge-tts`，免 key，需联网到微软语音端点）。

## 解析输入建清单

**清单唯一来源是用户输入，本 skill 没有默认范围**：用户没给任何文件夹/文件（包括只说"把简报做成播客""做最新一批"这类没附路径的话）→ 停下来向用户要，不得扫描任何项目的全库、不得自行挑"最新批次"代劳；索要时可以列一份只读候选（列到文件夹名/文件名即可，不打开文件内容评优劣）供用户拍板——**为提问而列举允许，代用户决定禁止**。

- 输入为**文件夹**（可多个）→ 递归收其下全部 `.md`，逐个按"简报契约"检查，合格者入清单（排除的文件名与原因进最终答复）；
- 输入为**具体 md 文件**（可多个）→ 同样逐个按契约检查，合格入清单；
- 两类可混合；清单按完整路径去重后排序（日期文件夹名→文件名）。

清单细则：

1. 篇数 N=简报 `### ` 行数（只数头行、标题级扫描，不算整读）。N=0（空简报）→ 不建稿不合成，汇报即可。
2. **拆分成集（硬规则）**：上限 15 篇/集。N≤15 → 一集（p1）；否则 `K=⌈N/15⌉`，按条目出现顺序切：p1…p(K−1) 各 15 篇、pK 有几篇算几篇（N 恰为 15 整除则无尾巴）。同一简报的集按 p1→pK 顺序入清单。**不均分、不丢篇、不重排、不按小节/类别边界切**——只按篇数顺序切。
3. **严格串行**：一次只推进一集，本集 mp3 落定前不碰下一集；**跳过规则（按集）**：该集 `podcast_*_p{k}.mp3` 已存在且稿内 `# 第N篇` 数=该集篇数 → 视为完成不再动（用户点名"重跑该刊/该集"时才删稿重来或只重合成）。

## 对谈稿格式（make_podcast.py 的输入约定）

只允许三类行，其余一律不许出现：

```markdown
# 第2篇 <该篇原标题>
[A] 今天聊《American Economic Review》2026年第9期这篇，标题是 Optimal Public Transportation Networks，讲的是雅加达全球最大BRT系统的线网优化。
[B] 有意思在这儿：他们利用雅加达公交大扩张的线路开通事件做需求模型，发现通勤者对候车时间的敏感度是在车上的两到三倍。
```

- `#` 注释行：合成忽略；其中 **`# 第N篇 <原标题>` 是该篇起始标记，N 按本集内出现顺序编号（本集第 1 篇记 1）**，断点续作靠它定位；本集↔全局篇号对应由稿头覆盖注释固定。
- `[A] `/`[B] ` 台词行：A=男声（默认 zh-CN-YunxiNeural）、B=女声（默认 zh-CN-XiaoxiaoNeural）。紧跟台词后的无标签续行并入同一句发声。
- 风格：口语问答，不许念 Markdown 符号；**每篇开场必须报出该条目出处（期刊名+年-期/卷期；出处行没有的直接读简报"出处："转述）与原标题**（标题照读，正文转述用中文）；**数字与结论只能取自该篇简报条目**，不得外推；一篇 150–400 字（约 1–2 分钟）。括注行（`（另涉…）`）只是分类信息，不作对谈事实源。
- 稿内必有：**头注释一行（写明 `本集覆盖简报第a–b篇`，全局篇号）**、开场白两三行（该简报的刊名/领域名+期次、本集共 M 篇、一句话钩子）、结尾一两句（收束+可预告下一集）；中间逐篇。

## 执行步骤（逐集串行循环）

0. 依赖检查（**在建好非空清单之后才做**；没有输入就只问不做，环境操作不算"往下走"的例外）：`python -c "import edge_tts"`；缺失则 `python -m pip install edge-tts`。
1. 按上文《解析输入建清单》一节建集清单。要不到输入、或全部文件都不合格 → 停在索要/汇报，一步不往下。
2. 建稿：在该简报所在的 `reports\{YYYYMMDD}\` 里写本集稿 `script_{stem}_{YYYYMMDD}_p{k}.md`（文件夹与稿都不碰简报本身）。建稿那次 Write 只含头注释（含覆盖篇号 a–b）+开场白，**第 1 篇也一律走后续 Edit 追加**。稿已存在（上次中断）→ 不重建，直接续写。
3. **逐篇改写**（主体循环）：本集共 M 篇，全局篇号 a…a+M−1；每次只读简报**覆盖范围内的一个 `### ` 条目块**（按全局篇号定位，前面的条目只数不细读，不要整读全篇），按上节格式写这篇对谈，以 `# 第k篇 <原标题>`（k 从 1 数到 M）开头追加到稿尾；核对无误再下一篇。中断续跑：数稿内已有最大 `# 第k篇`，先核对该篇块末行是完整台词（撕裂则修复该篇），再从 k+1 继续。
4. 本集全部条目写完，追加结尾（收束+可预告下一集/下一刊），稿本定稿。
5. 合成：
   ```
   python <skill>\scripts\make_podcast.py --script <该简报所在的日期文件夹>\script_{stem}_{YYYYMMDD}_p{k}.md
   ```
   打印 `segments=X to_synth=Y` 与 `OK ... est_min=...`。**非零退出=有段合成失败，直接重跑同一条命令**（已合成段自动跳过）；**同一条命令连续重跑 2 次仍非零退出→判该集失败**：停止重试，原因写进最终答复，**跳到清单下一集**——失败集不阻塞后续，"串行"是一次推进一集，不是死等。
6. 一集完成（或判失败跳集）后进清单下一集（清单已建，不再重问输入）；全部完成后最终答复：各集 mp3 路径与估算时长、所在日期文件夹、排除的非简报文件、跳过/无简报/失败的集及原因。

## 约束

- **处理范围只认用户输入**：清单只含用户明确给出的文件夹（递归其下全部 .md）或直接点名文件所覆盖的合格简报；不自行扫描、不自挑"最新批次"——没给输入就只向用户要（§解析输入建清单）。
- 逐篇读、逐篇写、逐篇追加；一次 Edit 只追加一篇——与简报 skill 同一套防上下文溢出纪律。
- 联网只允许经 `make_podcast.py`；不要调其他 TTS 服务、不下载任何音频之外的东西。
- 简报文件与上游数据目录（如 repec 的 `data\`、ncpssd 的 `snap\`）永远不动；只在简报所在日期文件夹下新增/修改 `script_*`、`podcast_*`、`cache_*`。
- **不为补简报触发上游管线**：某刊没简报、或简报缺成稿行——只报告、只跳过；绝不为了多出一集去跑采集/简报 skill。
- 集=一个简报的连续篇号段；不把多简报、多批次合并成一集，也绝不丢篇或做"精选摘要"压时长——长简报只按拆分成集规则顺序切。
- 换默认音色属于维护：见下节，不改脚本代码。

## 维护与排查

- **选/换音色**：`python -m edge_tts --list-voices | findstr zh-CN`，用 `--voice-a/--voice-b` 传入，如云健 `zh-CN-YunjianNeural`（新闻腔男声）、晓伊 `zh-CN-XiaoyiNeural`。
- **改一句重配**：直接改稿后重跑合成（哈希变了只重配那一句）；或删对应缓存段强制重配。
- **整集重来**：删 `cache_podcast_*` 目录再跑。
- **时长/内容异常**：检查台词行是否漏了 `[A]`/`[B]` 前缀（会被当续行并入上一句）、`# 第N篇` 与简报 `### ` 条目顺序是否对得上、简报条目是否缺 `---` 收尾线（缺=不合契约，回上游修）。
- **想升级本地模型**（CosyVoice2/F5-TTS，GPU）：只需把 `synth_one` 换成对应引擎调用，稿本格式不变——本 skill 的稿本是引擎无关的。

## 维护约定

- 本 skill 是 repec-podcast / ncpssd-podcast 的通用化继任：管线专属细节一律外置为"简报契约"，上游简报格式变更（增删小节、改收尾线、改成稿行）**必须与三条简报线同步拉平**，不许单侧放宽契约。
- `.claude\skills\podcast\` 与 `.dsh\skills\podcast\` 成对维护：SKILL.md 与 `scripts\make_podcast.py` 两处**逐字节一致**，改一处必同步另一处。
